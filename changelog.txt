= 0.1.5 =
* Placeholders: every held iframe shows a bundled decorative SVG (assets/images/{map,video,audio,post,embed}-placeholder.svg). SEOProCookieConsent_Thumbnails::KINDS maps services to kinds (YouTube/Vimeo video, Spotify/SoundCloud audio, X/Instagram/Facebook post, Google Maps map); other and custom services get embed. A cached YouTube/Vimeo thumbnail still wins. spcc-head.js reads the same images, with '*' as the fallback.
* Placeholders: a pixel height (alone or with a pixel width) sets min-height:64px instead of the stylesheet's 180px, so compact players (Spotify 80/152px, SoundCloud 166px) keep their height. spcc.js fit() uses a ResizeObserver to set data-spcc-fit 1-3 while the notice overflows: tighter spacing, then buttons only (sentence kept for screen readers and as the Load button's title), then the Load button only. Before, core responsive embeds under about 180px tall (16:9 on phones) clipped the notice.
* Front end: spcc.js checks the theme's button text against the button background (normal and hover) and, below 4.5:1, sets --spcc-btn-ink/--spcc-btn-ink-hover on body to the theme's background or strong text colour, then white or black. Rechecked on html/body class changes (Kadence dark mode switcher) and prefers-color-scheme changes. Before, Kadence dark mode gave palette 9 text on palette 1 (2.57:1).
* Consent records: Cookie settings shows the cookie's consent ID only with recording on and an existing choice, with a keyboard-accessible copy button and live success/failure feedback. Browser-only ID population keeps cached HTML visitor-independent. Administrator-only, nonce-protected POST lookup validates exact 32-character lowercase hexadecimal IDs and shows unexpired choices, UTC times, policy versions and snapshot hashes newest first in indexed pages of 100. Schema 3 adds a visitor-ID/record-ID index. No public read route. Document pseudonymous records and exclusion from WordPress's email-based personal data export/erase tools.

= 0.1.4 =
* Consent automation: stable data-spcc-action hooks on dialog buttons and data-spcc-toggle category inputs, preserving the banner's existing action names and all behaviour. Document the DOM contract, normal explicit-choice recording and decision not to fingerprint automated answers. Local autoconsent and Consent-O-Matic drafts are development-only, not yet upstream support.
* Blocker: the held iframe inside a placeholder is hidden with .spcc-embed[data-spcc-embed] iframe { display: none !important }. Before, site or theme rules of equal specificity loaded later (such as .spd-listing-map iframe { display: block; width: 100% !important }) showed the blank iframe beside the notice, squeezing it to one word per line on phones. Releasing still unwraps the iframe, so loaded embeds are unaffected.

= 0.1.3 =
* Import: turn on Keep consent records when local consent rows exist in Complianz Premium, Borlabs Cookie, Ultimate GDPR & CCPA, Real Cookie Banner, CookieAdmin or WPConsent tables, including when source settings are gone. Prepared SELECT 1 ... LIMIT 1 probes never read or copy record contents. Empty or missing tables, data requests, revisions alone and hosted providers leave recording unchanged. The normal dry run, import journal, changed-since checks and undo include the setting; repeated imports remain no-ops.
* Import: a selected page whose newest revision is an old autosave no longer stops the import with "A page revision could not be saved". Like core, the page's newest saved revision is the undo point; autosaves are skipped.
* Import: when a selected page gets the Cookie policy block (or [spcc_cookie_policy]) and Cookie policy is off, the import turns it on in the same journaled change, so undo turns it off again. Before, the block rendered nothing until Cookie policy was switched on by hand, leaving the cookie policy page without its list.
* Blocker: placeholders read an iframe's width and height as pixels only. With pixels on both, they keep the aspect ratio up to that width, as before. Otherwise each dimension is copied on its own (pixel width as a maximum, pixel height, or a percentage). So Kadence's Google Maps block (width="100%" height="100%") and Google's embed code (width="100%" height="450") fill their space; before, "100%" read as 100px and made a tiny box. The same applies to iframes held back after the page loads.
* Blocker: Google Maps placeholders show a bundled generic map image (assets/images/map-placeholder.svg) under the notice and its existing scrim, like video thumbnails. It is served from the plugin, so nothing reaches Google before consent.

= 0.1.2 =
* Menus: Appearance → Menus has a Cookie settings box that adds a custom link to #cookie-settings, in Title Case beside Title Case policy links; it is shown on a user's first visit. The automatic footer link goes just after the cookie policy page link, else just before the privacy policy link, in any footer menu (a footer theme location, or a menu named "footer", so widget and block menus count); otherwise at the end of the theme's footer menu, as before. Matched by page ID or address; an item with a submenu gets the link at the end instead. A published menu item linking to #cookie-settings anywhere means the owner placed it, so nothing is added.
* Consent records: Keep records for (days), 0–3650, separates evidence retention from browser choice lifetime. Default 0 follows the current choice lifetime; positive values use the longer period for both cron cleanup and record exports. Records never expire sooner than choices, and snapshot retention is unchanged.
* Consent records: private, canonical SHA-256 snapshots archive banner message templates and labels, category descriptions and service catalogue, local policy source, URL, modification time and revision ID, and plugin version. Settings/admin and policy saves deduplicate content, never visitor requests. Browser choices attach a known snapshot hash; missing, malformed and unknown hashes remain empty for old cached pages. Records CSV gains Snapshot and a second administrator-only, keyset-paged CSV exports archived content as JSON. Snapshot retention preserves every referenced archive; uninstall removes both per-site tables. Evidence of what was shown, not a compliance guarantee.
* Cleanup: two new leftover kinds, post meta keys and generated folders under uploads (removed with WP_Filesystem, only inside their source's own folder, never through a link; an emptied parent folder goes too). Complianz lists its _cmplz_ and cmplz_ post meta (973 scan markers, 257 remote-scan markers and 548 hide-banner values on one site) and uploads/complianz/cmp, css, js, placeholders, maxmind and tmp (8.2 MB there); other folders there, such as Premium's snapshots, are listed as kept. = 0.1.1 =
