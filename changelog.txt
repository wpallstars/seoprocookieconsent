= 1.0.17 =
* New: The Privacy policy's "Who we share it with" list adds analytics and advertising providers (#162). When the site was seen using a Statistics or Marketing service, it says data goes to them only if the visitor allows those cookies, and that some, such as social networks and advertising platforms, also use it for their own purposes. Omitted otherwise; Your own wording is unchanged.
* Fixed: Meta Pixel for WordPress (Meta's own plugin, 5.2 and later) is held properly with Cookie consent on (#158). It set the _fbp and _fbc marketing cookies from the server on a visitor's first page, before any choice; its server events (Conversions API) were not held; and the pixel never started, even after consent, because its new inline start-up code ran before the held loader. Now the browser sets Meta's own state cookie (wc_facebook_signals_state) to "active" only while Meta Pixel is allowed and removes it otherwise; for a visitor without "active" the server sends no server events and takes back the _fbp and _fbc cookies Meta set before this plugin loaded; and the pixel's inline start-up and tracking code is held with its loader, so it runs after it once allowed. Pages look the same to every visitor, so page caches keep working. Withdrawing marketing deletes _fbc as well as _fbp. Sites without Meta's plugins are unchanged.

= 0.1.3 =
* Import: turn on Keep consent records when local consent rows exist in Complianz Premium, Borlabs Cookie, Ultimate GDPR & CCPA, Real Cookie Banner, CookieAdmin or WPConsent tables, including when source settings are gone. Prepared SELECT 1 ... LIMIT 1 probes never read or copy record contents. Empty or missing tables, data requests, revisions alone and hosted providers leave recording unchanged. The normal dry run, import journal, changed-since checks and undo include the setting; repeated imports remain no-ops.
* Import: a selected page whose newest revision is an old autosave no longer stops the import with "A page revision could not be saved". Like core, the page's newest saved revision is the undo point; autosaves are skipped.
* Import: when a selected page gets the Cookie policy block (or [spcc_cookie_policy]) and Cookie policy is off, the import turns it on in the same journaled change, so undo turns it off again. Before, the block rendered nothing until Cookie policy was switched on by hand, leaving the cookie policy page without its list.
* Blocker: placeholders read an iframe's width and height as pixels only. With pixels on both, they keep the aspect ratio up to that width, as before. Otherwise each dimension is copied on its own (pixel width as a maximum, pixel height, or a percentage). So Kadence's Google Maps block (width="100%" height="100%") and Google's embed code (width="100%" height="450") fill their space; before, "100%" read as 100px and made a tiny box. The same applies to iframes held back after the page loads.
* Blocker: Google Maps placeholders show a bundled generic map image (assets/images/map-placeholder.svg) under the notice and its existing scrim, like video thumbnails. It is served from the plugin, so nothing reaches Google before consent.
